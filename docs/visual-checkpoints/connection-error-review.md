# ConnectionError visual checkpoint

ConnectionError was upgraded from a generic connection-error placeholder with an Activate/Deactivate toggle and no failed request, endpoint, status code, incident record, retry behavior, or recovery evidence. It has been removed rather than implying that a service is down, that a retry occurred, or that an issue was resolved. No endpoint, service owner, request context, outage cause, uptime result, retry success, incident, support response, recovery state, or API status is represented.

Files: `connection-error-desktop.webp`, `connection-error-mobile.png`.

The 390px capture was reviewed for readable wrapped connection-details-unavailable disclosure, stacked endpoint/request, retry/recovery, health/observability, and support/audit readiness cards, explicit no-diagnosis warning, and absence of horizontal overflow.
