# AutoResponder visual checkpoint

AutoResponder was already hardened to a truthful unavailable automated-response boundary. The previous screen exposed an authenticated shell with New, Search, Settings, loading, and empty-item behavior, but no verified conversation source, trigger evaluator, recipient permission, template registry, AI provider, scheduling queue, delivery provider, opt-out flow, or audit contract was connected. Those controls were removed because the screen cannot establish that an automated reply would be safe, authorized, or delivered. No conversation, trigger, recipient, message, template, response, delivery receipt, conversation state, model, prompt, generated text, tone, classification, tool call, safety decision, autonomous response, email, push, SMS, chat, webhook, schedule, queue, retry, unsubscribe, or external notification is read, created, invoked, sent, or stored.

Files: `auto-responder-desktop.webp`, `auto-responder-mobile.png`.

The 390px capture was reviewed for readable wrapped automated-response disclosure, stacked reply/AI/delivery boundary cards, visible notification/AI/privacy/contact links, sensitive-data warning, and absence of horizontal overflow.
